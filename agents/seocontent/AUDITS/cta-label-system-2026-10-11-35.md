## قواعد یکدست‌سازی

۱. **یک اقدام، یک نام** (از ۱۸:۰۵): تماس تلفنی همیشه «تماس با کارشناس فروش»؛ درخواست فرم همیشه «درخواست تماس» / «ثبت درخواست تماس».
۲. **برچسب = فعل + موضوع مشخص:** «ثبت درخواست تماس»، «مشاهدهٔ جزئیات تور»، «اشتراک‌گذاری در واتس‌اپ». برچسبِ بدون موضوع ممنوع.
۳. **«مشاهدهٔ بیشتر» ممنوع:** هیچ‌جا به‌تنهایی نمی‌نشیند؛ همیشه موضوع دارد («مشاهدهٔ جزئیات تور»).
۴. **«ورود» / «شروع رایگان» / «اقدام اصلی» ممنوع:** محصول ثبت‌نام و ورود ندارد؛ پیش‌فرض‌ها برچسب واقعی می‌گیرند.
۵. **تفکیک ثبت/ارسال:** «ثبت» فقط برای فرم (درخواست تماس)؛ «ارسال» فقط برای پیام. دکمهٔ هر دو فرم، «ثبت درخواست تماس» است.
۶. **پیش‌فرض کامپوننت هم کپی است** (از ۱۸:۰۵): برچسب‌های پیش‌فرض navbar و hero با واقعی‌های سایت پر می‌شوند.

## دستور اجرایی (برای dev، فاز ۴)

**D1. برچسب اصلی ناوبری (هم‌راستا با A3 اجرا ۱۸:۰۵).**
- فایل: `site/app/layout.tsx` خط ۱۰۴
- رشتهٔ فعلی: ``تماس با ${s.CONTACT_NAME}``
- جایگزین: `تماس با کارشناس فروش`
- یادداشت: نام کارشناس از دکمه حذف می‌شود ولی در فوتر (ردیف ۴ موجودی) و کارت تماس می‌ماند.

**D2. پیش‌فرض navbar.**
- فایل: `site/components/blocks/navbar.tsx` خط ۳۰
- رشتهٔ فعلی: `primary = { label: "شروع رایگان" }, secondary = { label: "ورود" }`
- جایگزین: `primary = { label: "تماس با کارشناس فروش" }, secondary = { label: "درخواست تماس" }`

**D3. پیش‌فرض hero.**
- فایل: `site/components/blocks/hero.tsx` خط ۲۷
- رشتهٔ فعلی: `primary = { label: "اقدام اصلی" }, secondary = { label: "مشاهدهٔ بیشتر" }`
- جایگزین: `primary = { label: "تماس با کارشناس فروش" }, secondary = { label: "مشاهدهٔ جزئیات تور" }`

**D4. دکمهٔ submit فرم تماس.**
- فایل: `site/components/blocks/contact.tsx` خط ۴۴
- رشتهٔ فعلی (حالت عادی): `ارسال پیام`
- جایگزین: `ثبت درخواست تماس`
- یادداشت: حالت‌های «در حال ارسال…» و «پیام ثبت شد» همان‌جا بازبینی شوند و با «درخواستتان ثبت شد» یکدست شوند.

**D5. حالت busy فرم callback.**
- فایل: `site/components/site/CallbackForm.tsx` خط ۱۶۹
- رشتهٔ فعلی: `در حال ثبت…`
- جایگزین: `در حال ارسال…`
