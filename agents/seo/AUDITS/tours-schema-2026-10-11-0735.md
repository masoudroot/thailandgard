# ممیزی اسکیمای صفحه‌های تور | ساعت ۰۷:۳۵، ۱۹ مهر ۱۴۰۵

## وضعیت موجود (`site/app/tours/[slug]/page.tsx`)

روی هر صفحهٔ `/tours/[slug]` دو `<script type="application/ld+json">` جدا تزریق می‌شود:

۱) **TouristTrip**: فیلدها: `name` (عنوان تور)، `description` (خلاصه)، `touristType` (از دادهٔ واقعی هر تور)، `itinerary` از نوع `ItemList` با `ListItem`های روزبه‌روز (نام: «روز ۷ | بازگشت، توضیح برنامهٔ آن روز»).

۲) **Offer**: فقط داخل TouristTrip: `availability` (بر اساس `tour.active`: InStock یا OutOfStock) و `url`. قیمت به‌عمد از اسکیما حذف شده (کامنت داخل کد): صفحه خودش می‌گوید قیمت‌ها «شروع قیمت» و تقریبی‌اند و با تاریخ سفر و ظرفیت هتل تغییر می‌کنند؛ پس `price` واقعی و ثابتی وجود ندارد و نگه‌داشتنش در اسکیما گمراه‌کننده بود. قیمت نمایشی HTML سر جایش هست.

۳) **FAQPage**: ساخته‌شده از `tour.faqs` (زنجیرهٔ محتوا ← اسکیما سالم است).

بردکرامب بصری صفحه سه سطح دارد: خانه ← تورها ← عنوان کوتاه تور. هر سه لینک معتبرند: صفحهٔ ایندکس `/tours` وجود دارد (`app/tours/page.tsx`).

## خلأها

- **نبود BreadcrumbList** روی صفحه‌های تور؛ همان خلأی که در اجرای ۰۷:۰۵ برای راهنماها یافتیم و دیفش را آماده کردیم. بردکرامب بصری هست ولی هیچ JSON-LD بردکرامبی نیست.
- **نبود image**: در `site/lib/tours.ts` فیلد تصویر تعریف نشده و صفحهٔ تور هم عکسی نشان نمی‌دهد؛ پس چیزی برای تزریق به اسکیما نیست. این قلم را برای dev نمی‌فرستیم چون اول باید عکس واقعی تولید شود.
- **aggregateRating نداریم و نمی‌سازیم**: هیچ دادهٔ امتیاز/نظری از کاربر واقعی وجود ندارد. به‌عمد پیشنهادش نمی‌دهیم؛ ساختن عدد در اسکیما هم خلاف سیاست گوگل است هم خلاف صداقت داده.
- قیمت Offer: تیم قبلی آگاهانه حذفش کرده بود (بالا ببینید)؛ پس جزو خلأها نمی‌آید و فقط یادآوری شد.

## دیف آماده برای dev (نوبت بعد): الگوی کپی‌دقیق BreadcrumbList

فایل: `site/app/tours/[slug]/page.tsx`

در این صفحه برخلاف راهنماها، JSON-LDها تگ‌های جداگانه‌اند (بدون `@graph`). کم‌ریسک‌ترین دیف: یک تگ سوم به همان سبک، بعد از تگ FAQ.

کد فعلی (لنگر یکتا):
```tsx
      <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(tripJsonLd) }} />
      <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(faqJsonLd) }} />
```

کد تازه (یک آبجکت و یک تگ اضافه می‌شود؛ بقیه دست نمی‌خورد):
```tsx
  const breadcrumbJsonLd = {
    "@context": "https://schema.org",
    "@type": "BreadcrumbList",
    itemListElement: [
      { "@type": "ListItem", position: 1, name: "خانه", item: `${SITE_URL}/` },
      { "@type": "ListItem", position: 2, name: "تورها", item: `${SITE_URL}/tours` },
      { "@type": "ListItem", position: 3, name: tour.shortTitle, item: `${SITE_URL}/tours/${tour.slug}` },
    ],
  };
```
و در JSX:
```tsx
      <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(tripJsonLd) }} />
      <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(faqJsonLd) }} />
      <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(breadcrumbJsonLd) }} />
```

یادداشت یکدستی: بردکرامب بصری دقیقاً همین سه سطح را نشان می‌دهد (خانه ← تورها ← `shortTitle`)؛ اسکیما با آن یکدست است. هر سه `item` URL معتبرند.

## بلوکر ثبت‌شده
مثل نوبت قبل: PageSpeed واقعی بدون دامنهٔ اصلی (دست مسعود) ممکن نیست؛ اثر این اسکیما روی Core Web Vitals را نمی‌توان با عدد واقعی سنجید. ریسک تغییر صفر است (یک `<script>` تازه، بدون اثر روی رندر).
