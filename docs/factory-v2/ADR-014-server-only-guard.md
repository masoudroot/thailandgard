# ADR-014: نگهبان زمان اجرای server-only برای Gateway، بدون وابستگی تازه

- وضعیت: پذیرفته‌شده در بستهٔ R3B (۱۴۰۵/۰۸/۰۹)
- دامنه: ماژول‌های `site/lib/factory/gateway/` و
  `site/lib/factory/tick/gateway-attempt-cycle.ts`

## زمینه

ماژول‌های Gateway با کلید service_role به PostgREST می‌رسند و
فراخوان Provider را انجام می‌دهند. اگر این ماژول‌ها به باندل
مرورگر راه پیدا کنند، کلید سروری و عملیات حساس افشا می‌شود.
بستهٔ رسمی این مرز، `server-only` است که با import، بیلد
کلاینت را می‌شکند.

## بررسی

- `server-only` در `site/package-lock.json` نیست (راستی‌آزمایی
  شده). افزودنش وابستگی تازه است و طبق قانون مخزن، ADR و تأیید
  صریح می‌خواهد.
- همهٔ ماژول‌های Gateway همین حالا در اولین خط،
  `server-guard.ts` را وارد می‌کنند که با دیدن `window` همان‌جا
  throw می‌کند. این نگهبان، مرز را در زمان اجرا نگه می‌دارد.
- در این شاخه، هیچ فایلی بیرون از دایرکتوری gateway و تست‌ها،
  ماژول‌های Gateway را وارد نمی‌کند (راستی‌آزمایی با grep روی
  `app/` و `lib/` و `components/`).

## تصمیم

- در R3B وابستگی `server-only` اضافه نمی‌شود.
- نگهبان زمان اجرا می‌ماند و تست
  `r3b-server-guard.test.ts` آن را ثابت می‌کند: با window
  تعریف‌شده، import رد می‌شود و بدون window موفق است.
- import صریح `server-only` به بستهٔ بعدی موکول می‌شود و آن
  بسته باید تأیید صریح برای وابستگی تازه بگیرد.

## پیامد

- هیچ کلید یا پاسخ حساسی در باندل کلاینت قرار نمی‌گیرد؛ مرز
  فعلی، زمان اجراست نه زمان بیلد.
- اگر روزی کامپوننتی ماژول Gateway را وارد کند، در زمان اجرا
  می‌شکند (نه در زمان بیلد). همین محدودیت، دلیل موکول شدن
  import صریح است، نه دلیل دور زدن آن.
