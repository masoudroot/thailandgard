# دستور برگشت اضطراری (Rollback Runbook) — نسخهٔ نهایی

**کد کار:** P0-06 | **تاریخ نهایی‌سازی:** ۲۰۲۶-۱۰-۲۵ | **تمرین dry-run:** انجام شد (بدون اعمال واقعی)
**تصمیم‌گیرنده:** Leader (مسعود اکبری)

برای سایت زندهٔ `thailandgard.ir` که روی ورسل اجرا می‌شود. این سند جایگزین نسخهٔ ایشو #۱۹۹ است.

## ۱. چه زمانی برگردیم؟

- سایت بالا نمی‌آید یا خطای ۵xx پیوسته می‌دهد.
- فرم تماس/تکمیل سفارش خراب شده.
- جهش شدید در سئو (canonical/noindex اشتباه، حذف صفحات از ایندکس).
- یک دیپلوی جدید Production ناسالم بالا آمده.
- یک ورک‌فلو یا کار خودکار خرابی به پا کرده.

اصل: اول جلوی خون‌ریزی را بگیر، بعد علت را بررسی کن.

## ۲. مسیر ۱ — سریع‌ترین: برگشت دیپلوی ورسل (بدون تغییر کد)

برای هر خرابی سمت سایت، این اولین کار است. هدف: زیر ۵ دقیقه.

1. داشبورد ورسل → پروژهٔ `thailandgard` → تب Deployments.
2. آخرین دیپلوی Production سالم قبل از خرابی را پیدا کن.
3. از منوی ⋯ همان دیپلوی: **Promote to Production** (یا Redeploy → Production).
4. تست کن: صفحهٔ اصلی و /tours و /guide باید ۲۰۰ بدهند.

معادل خط فرمان (نیاز به لاگین ورسل؛ روی این ماشین انجام شده است):

```bash
vercel ls thailandgard     # دیدن دیپلوی‌ها
vercel rollback            # برگشت به دیپلوی قبلی production
```

## ۳. مسیر ۲ — برگشت کد (اگر ریشهٔ خرابی در کد main باشد)

نقطهٔ امن (baseline): تگ `production-baseline-2026-10-24` = کامیت `fdf5152fd9993346a3ce94eb4f8d9b9182995b79`.

### الف) روش نرم (تاریخ تمیز) — روی گیت‌هاب

1. PRهای `#202`، `#201`، `#200` را به ترتیب معکوس (۲۰۲ سپس ۲۰۱ سپس ۲۰۰) باز کن.
2. روی هرکدام دکمهٔ **Revert** را بزن؛ یک PR بازگشت ساخته می‌شود؛ آن را merge کن.
3. نتیجه: کد دقیقاً به وضعیت baseline برمی‌گردد و تاریخ روشن می‌ماند.
   - تمرین انجام‌شده: بازگشت PR #201 روی main بدون هیچ تعارضی اعمال شد (۲۹ فایل؛ ۲۸۰۲ خط اضافه و ۷۹۵ خط حذف).

### ب) روش سخت و فوری (اضطراری) — force

```bash
git push --force-with-lease origin fdf5152fd9993346a3ce94eb4f8d9b9182995b79:refs/heads/main
```

- main محافظت شاخه ندارد (بررسی شد؛ الان این کار ممکن است).
- main را دقیقاً به baseline برمی‌گرداند؛ ورسل خودش از main دوباره build می‌کند.
- فقط با تأیید Leader. هرچه از main حذف شود در تاریخ گیت باقی می‌ماند و قابل بازگردانی است.

### ج) چک بعد از برگشت کد

- `curl -s -o /dev/null -w '%{http_code}' https://thailandgard.ir` باید 200 بدهد.
- `curl -sL https://thailandgard.ir/sitemap.xml | sha256sum` باید برابر `d22a8da741e7fe705e3f33b92a6d4ec1d4b0ebf3911a87695d96273f543008ae` باشد.
- در ورسل: دیپلوی جدید Production سبز شده و روی آلیاس thailandgard.ir نشسته باشد.

## ۴. مسیر ۳ — خاموش‌کردن فوری کارخانهٔ جدید

این فقط زمانی لازم است که ریشهٔ خرابی خودِ سیستم جدید باشد (در این مرحله بعید است؛ هنوز فعال نشده):

- ورسل: متغیر `FACTORY_RUNTIME` را حذف/خالی کن و Deploy مجدد بزن.
- ورک‌فلوهای جدید اثری روی سایت زنده ندارند؛ Factory CI فقط تست می‌گیرد و gsc-baseline دستی است.
- مسیرهای `/api/factory/*` بدون توکن چیزی اجرا نمی‌کنند.
