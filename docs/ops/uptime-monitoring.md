# پایش زندهٔ سایت (Q4-01)

هدف: بدانیم سایت برای بازدیدکننده بالا می‌آید یا نه، بدون هیچ سرویس پولی.

## چه چیزی بررسی می‌شود

| نقطه | آدرس | شرط سالم بودن |
|---|---|---|
| سرویس سلامت | `/api/health` | پاسخ JSON با `"status":"ok"` |
| صفحهٔ اصلی | `/` | کد ۲۰۰ و محتوای فارسی صفحه (بیش از ۵۰۰۰ نویسه) |
| صفحهٔ تور | `/tours/phuket-7-days` | کد ۲۰۰ و محتوای صفحهٔ تور |

## چطور کار می‌کند

- هر ۱۵ دقیقه: `.github/workflows/uptime-probe.yml` اجرا می‌شود.
- هر نقطه سه بار با فاصلهٔ ۵ ثانیه تلاش می‌کند؛ خرابی فقط وقتی اعلام می‌شود که **هر سه تلاش** شکست بخورد (لرزش شبکه هشدار نمی‌سازد).
- وضعیت در Issue با برچسب `ops` نگه داشته می‌شود:
  - خراب شد و Issue باز نیست: Issue جدید ساخته می‌شود.
  - خراب ماند و ۶ ساعت از آخرین به‌روزرسانی گذشته: یادآوری روی همان Issue.
  - سالم شد و Issue باز است: پیام بهبودی و بستن Issue.
- اگر ران شکست بخورد (کد ۱) در تب Actions هم قرمز دیده می‌شود، پس هشدار فقط به Issue وابسته نیست.

## کانال هشدار

**الان:** Issue گیت‌هاب با برچسب `ops` (کار می‌کند، بدون سکرت اضافه).

**تلگرام (اختیاری، پیشنهادشده):** دو سکرت مخزن را اضافه کنید:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`

از `Settings → Secrets and variables → Actions → New repository secret`. همین دو نام در `cycle-watchdog.yml` هم استفاده می‌شوند؛ الان ساخته نشده‌اند، پس هشدارهای آن watchdog هم بی‌صدا هستند. بعد از افزودن، همان اجرای بعدی probe پیام را به تلگرام می‌فرستد.

## آزمون دستی کانال هشدار

```bash
gh workflow run uptime-probe.yml -f simulate_failure=true
gh run list --workflow=uptime-probe.yml --limit 1
```

اجرای شبیه‌سازی‌شده عمداً قرمز می‌شود، یک Issue با عنوان `🚨 uptime: سایت در دسترس نیست` می‌سازد و (اگر تلگرام تنظیم باشد) پیام می‌فرستد. بعد از بررسی، Issue را ببندید؛ اجرای عادی بعدی وضعیت سالم را می‌بیند و کاری نمی‌کند.

## محدودیت‌ها

- probe از رانر گیت‌هاب اجرا می‌شود، پس خرابی شبکهٔ داخلی ایران یا مسدود شدن از سمت کاربران را نمی‌بیند؛ فقط «سایت از بیرون بالا می‌آید یا نه» را می‌گوید.
- حداکثر تأخیر تشخیص ۱۵ دقیقه به‌علاوهٔ سه تلاش (حدود ۱۵ ثانیه).
- این پایش جای APM و لاگ خطای سمت کاربر را نمی‌گیرد؛ آن کار Q4-05 و Clarity است.

## فایل‌ها

- `site/factory/tests/uptime-probe.test.ts` — ۱۴ تست (تلاش مجدد، ماشین وضعیت، پیام، کانال تلگرام).
- `.github/workflows/uptime-probe.yml` — زمان‌بندی، اجرای دستی، آپلود گزارش.
